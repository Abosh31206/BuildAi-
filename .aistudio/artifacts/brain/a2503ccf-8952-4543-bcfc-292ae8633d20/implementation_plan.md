# Construction Standards Library — Архитектура и План Реализации (BuildAI KZ)

> [!IMPORTANT]
> **Архитектурный этап**: Реализация кода модуля начнётся только после подтверждения архитектуры и плана. Существующие калькуляторы (10 шт.), Normative AI, 2D CAD, 3D WebGL генератор и генератор альбомов ПД сохраняются в полном объёме.

---

### User Review & Critical Decisions

- **Назначение модуля**: Централизованная цифровая библиотека нормативных документов Республики Казахстан (ГОСТ, СНиП, СП РК, СН РК, СТ РК, НТД) с проверкой статусов («Действует», «Заменен», «Отменен»), встроенным просмотрщиком PDF (масштаб, поиск, постраничная навигация, оглавление), админ-панелью управления и интеграцией с Normative AI.
- **Совместимость с Vercel**: Vercel Serverless имеет read-only файловую систему и эфемерный `/tmp`. Хранение метаданных и бинарных PDF организуется через внешнее объектное хранилище (S3/Cloud Storage/Supabase Storage) или безопасные проксируемые официальные CDN, а не на локальном диске Vercel.
- **Отказ от вымышленных данных**: Если документ отсутствует в оцифрованном виде или закрыт авторским правом, система честно сообщает об этом, отображает карточку с верифицированными метаданными и даёт прямую ссылку на официальный реестр Комитета по делам строительства и ЖКХ МПС РК или КазСтандарт.

## 3. Схема базы данных

Реляционная схема (совместимая с PostgreSQL/Cloud SQL/Supabase и TypeScript интерфейсами):

### Таблица `standards_documents` (Основные метаданные)
| Колонка | Тип | Описание |
|---|---|---|
| `id` | `UUID / TEXT` PK | Уникальный идентификатор документа |
| `document_number` | `VARCHAR(100)` INDEX | Официальный шифр (напр., `СП РК 5.03-107-2013`) |
| `document_type` | `VARCHAR(20)` | `SP_RK`, `SN_RK`, `GOST`, `ST_RK`, `SNIP`, `NTD` |
| `official_title_ru` | `TEXT` | Официальное наименование на русском языке |
| `official_title_kk` | `TEXT` | Ресми атауы қазақ тілінде |
| `document_status` | `VARCHAR(30)` | `ACTIVE` (действует), `REPLACED` (заменен), `CANCELLED` (отменен), `UNCONFIRMED` |
| `industry_category` | `VARCHAR(50)` | Несущие конструкции, Сейсмика, Основания, Климатология, Инженерия, Пожарная безопасность |
| `publication_date` | `DATE` | Дата принятия/утверждения приказом Комитета МПС РК |
| `effective_date` | `DATE` | Дата введения в действие |
| `revision_number` | `VARCHAR(50)` | Номер/год редакции (с изменениями и дополнениями) |
| `replaced_by_id` | `UUID` FK | Ссылка на документ, пришедший на замену |
| `replaced_by_number`| `VARCHAR(100)` | Шифр заменяющего норматива (для обратной совместимости) |
| `page_count` | `INTEGER` | Количество страниц в официальном издании |
| `source_name` | `VARCHAR(200)` | Наименование источника (напр., `Комитет по делам строительства МПС РК`, `КазСтандарт`) |
| `source_url` | `TEXT` | Прямая ссылка на официальный реестр |
| `access_rights` | `VARCHAR(30)` | `VIEW_AND_DOWNLOAD`, `VIEW_ONLY`, `OFFICIAL_LINK_ONLY` |
| `last_verified_at` | `TIMESTAMP` | Дата и время последней верификации статуса экспертом |

### Таблица `standards_files` (Файловые атрибуты)
| Колонка | Тип | Описание |
|---|---|---|
| `id` | `UUID` PK | Идентификатор файла |
| `document_id` | `UUID` FK | Внешний ключ на `standards_documents` |
| `file_url` | `TEXT` | Защищённый URL к файлу (Cloud Storage / S3 / Signed URL) |
| `file_format` | `VARCHAR(10)` | `PDF`, `DJVU` |
| `file_size_bytes` | `BIGINT` | Размер файла в байтах |
| `checksum_sha256` | `VARCHAR(64)` | Контрольная сумма SHA-256 для защиты от повреждений и дублей |
| `is_ocr_completed` | `BOOLEAN` | Флаг завершения извлечения текста |

### Таблица `standards_clauses` (Пункты и разделы для поиска и AI)
| Колонка | Тип | Описание |
|---|---|---|
| `id` | `UUID` PK | Идентификатор пункта |
| `document_id` | `UUID` FK | Ссылка на норматив |
| `clause_number` | `VARCHAR(50)` | Номер пункта/таблицы (напр., `п. 5.2.11`, `Таблица 4.1`) |
| `section_title` | `TEXT` | Наименование раздела |
| `content_ru` | `TEXT` | Точный текст пункта на русском языке |
| `content_kk` | `TEXT` | Нақты мәтіні қазақ тілінде |
| `page_number` | `INTEGER` | Номер страницы в официальном PDF для быстрого перехода |

## 4. Схема хранения PDF и извлечённого текста

1. **Файлы PDF**:
   - На Vercel запрещено локальное сохранение в `public/uploads` или `dist/`, так как файловая система эфемерна.
   - **Архитектура хранилища**:
     - *Вариант А (Бесплатный/Open Source)*: Supabase Storage (500 МБ бесплатно) или Firebase Storage с ограничением доступа по CORS и токенам.
     - *Вариант Б (Прямые проверенные ссылки)*: Хранение проверенных официальных URL с проксированием заголовков Content-Disposition через серверный эндпоинт `/api/standards/proxy-pdf` (для обхода CORS при встроенном рендеринге).
     - *Вариант В (Встроенные эталонные документы)*: Небольшой набор ключевых общедоступных стандартов (СП РК 5.03-107-2013, СП РК 2.04-01-2017 и др.) хранится в оптимизированном сжатом виде, загружаемом по требованию.

2. **Извлечённый текст и поисковый индекс**:
   - Текст разбивается на чанки с привязкой к номерам пунктов и страниц (`clause_number`, `page_number`).
   - Для поиска без сторонних платных БД используется:
     - На сервере: полнотекстовый поиск PostgreSQL (`to_tsvector('russian', content)`) либо встроенный легковесный индекс MiniSearch/Fuse.js.
     - На клиенте: мгновенный фильтр по метаданным и номерам с подсветкой совпадений.

## 6. Библиотеки для просмотра PDF и поиска

### Рекомендуемые бесплатные open-source библиотеки:
1. **Просмотр PDF**:
   - `pdfjs-dist` (Mozilla PDF.js v4) + легковесная обертка на React Canvas.
   - *Преимущества*: 100% бесплатно, лицензия Apache 2.0, полная поддержка рендеринга текста, векторной графики, поиска ключевых слов прямо по canvas-текстовому слою (`TextLayer`), поддержка масштабирования от 50% до 300%, переход по страницам и оглавлению (PDF Document Outline / Bookmarks).
   - Никаких платных зависимостей (PDFTron, PSPDFKit не требуются).
2. **Клиентский быстрый поиск**:
   - `minisearch` или `fuse.js` (легковесные, zero-dependency, быстрый нечеткий поиск по русским и казахским символам с опечатками).
3. **Парсинг CSV/XLSX для админ-импорта**:
   - `papaparse` для CSV импорта нормативных реестров (0.01s на 10 000 строк).

## 7. План импорта и проверки документов

1. **Ручной ввод**:
   - Инженерная веб-форма с валидацией обязательных полей (официальный номер, название RU/KK, статус, дата вступления, ссылка на источник).
2. **Пакетный импорт (CSV / XLSX)**:
   - Шаблон с колонками: `Number, TitleRu, TitleKk, Type, Status, PublicationDate, EffectiveDate, SourceUrl, ReplacedBy`.
   - Автоматическая валидация дубликатов по номеру и SHA-256 хэшу файла.
3. **Система верификации статусов**:
   - Хранение даты последней проверки (`lastVerifiedAt`).
   - Фиксация статусов на основе официальных приказов Комитета по делам строительства и ЖКХ Министерства промышленности и строительства РК.
   - Запрет на отображение недействующих документов без явного красного/оранжевого бейджа «Заменен / Отменен» и ссылки на новый документ.

## 9. Ограничения по доступности, авторским правам и полноте базы

1. **Авторские права и официальные источники**:
   - Строительные правила (СП РК), строительные нормы (СН РК) и государственные нормативы РК являются официальными нормативными правовыми актами (НПА). Согласно Закону РК «Об авторском праве и смежных правах» (ст. 8), официальные документы государственных органов и официальные переводы не являются объектами авторского права.
   - Однако некоторые стандарты (ГОСТ, СТ РК) могут распространяться институтами стандартизации (КазСтандарт) на особых условиях.
   - Для документов с ограниченным распространением BuildAI KZ реализует режим **«Карточка метаданных + Официальная ссылка на первоисточник»**, не публикуя защищенный файл самовольно.
2. **Полнота коллекции**:
   - В интерфейсе обязательно размещается дисклеймер:
     *«Библиотека BuildAI KZ находится в процессе планомерного наполнения и верификации. Наличие документа проверяется по официальному реестру Комитета МПС РК. Если необходимый норматив отсутствует, воспользуйтесь ссылкой на государственный реестр»*.

## 10. Пошаговый план реализации

1. **Шаг 1: Типы данных и реестр нормативных документов**:
   - Расширение типов в `src/modules/standards/types/index.ts` (поля `documentNumber`, `officialTitle`, `documentStatus`, `revision`, `replacedBy`, `accessRights`, `searchableText` и др.).
   - Формирование верифицированного начального реестра нормативов РК в `src/modules/standards/data/initialStandardsRegistry.ts`.
2. **Шаг 2: Встроенный PDF Viewer**:
   - Создание компонента `EmbeddedPdfViewer` на базе `pdfjs-dist` с постраничной навигацией, масштабированием (50%–300%), поиском текста в документе, переходом к странице и полноэкранным режимом.
   - Информационный fallback-компонент на случай отсутствия бинарного файла или ограниченных прав.
3. **Шаг 3: Каталог библиотеки и фильтрация**:
   - Строка поиска, фильтры по типу (СП, СН, ГОСТ, СТ, СНиП), отрасли (несущие конструкции, сейсмика, геология, климатология, отделка), статусу («Действует», «Заменен», «Отменен») и годам.
   - Карточки документов и альтернативное компактное табличное представление.
4. **Шаг 4: Админ-панель управления**:
   - Добавление и редактирование документов, валидация полей, проверка дубликатов по номеру.
   - Импорт из CSV/XLSX.
5. **Шаг 5: Интеграция с Normative AI**:
   - Двусторонняя связь: Normative AI выдаёт точный пункт и открывает встроенный просмотрщик на нужной странице.
6. **Шаг 6: Навигация в Header**:
   - Добавление пункта «Нормативная библиотека» в главное меню и мобильную панель.
   - Локализация всех строк (RU / KK).
7. **Шаг 7: Аудит, сборка и Vercel-верификация**:
   - Проверка `tsc --noEmit` и `npm run build` для гарантии нулевых ошибок.
